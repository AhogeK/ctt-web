### 减少动效偏好（2026-10-27 · v0.68.0 · 已提交 3f0de37 / c6c4215 / 9b2b327 / da64423）
- `src/stores/motion.ts`：三态 `system|reduce|full`，独立存储键 `ctt.motion`（与主题键分离：暗色与动效可以各选各的）；
  `watch([preference, prefersReducedMotion], …, { immediate, flush: 'sync' })` 统一写 `<html data-motion>`
  ⇒ 跨标签页 / OS 改动 / 首读一条路径。
- **属性承载「结论」而非「选择」**（本轮审查改口径）：`reduce`（用户选减少 **或** 系统要求减少）· `full`（用户选完整，**压过**系统）· 无属性（都没要求）。
  CSS 无法把媒体查询与存储值合并 ⇒ 合并由 store 负责，样式表只读属性。
- **两条实测抓出的真缺陷（首版口径错）**：① 属性镜像「选择」时，媒体查询仍管其余 ⇒ 用户选「完整动效」无法恢复落地页入场
  （那些声明在 `no-preference` 内）；② 用户选「减少动效」时动画仍存在，只被归零时长 ⇒ **`animation-delay` 仍生效** ⇒
  落地页文案先隐身 **70ms**、面板 440ms 才出现（系统减少时反而无此问题，因为动画压根不存在）。
- **修法**：删掉全部 4 处 `no-preference` 媒体查询门控，改为属性驱动（`html:not([data-motion='reduce'])`）；
  `main.css` / `AuthLayout.css` / `LeaderboardView` / `TimeOfDayPanel`（画布动画读 `isReduced`）四处媒体查询一并统一。
- **删掉全部 5 处 `motion-reduce:` 变体**：Tailwind 变体只认媒体查询，认不到用户选择 ⇒ 交由全局规则统一覆盖。
- Preferences 第三个区（跟随系统 / 减少动效 / 完整动效，各带一行说明 + 右上「当前：X」解析值）；`Monitor` 与主题区"跟随系统"共用图标语义。
- 验证：单测 · E2E settings（含两条新回归：reduce 时落地页入场**不存在**、full 在系统要求减少时仍恢复）· type-check · build ·
  `check:i18n` · oxlint；三视口视觉复核（1440 亮英文 / 1440 暗中文 / 375 亮英文，`overflowX=0`）。
- **与计划的两处偏差（已裁决 · 理由记入计划与领域文件）**：① 「与 media query 合并」的实现位置从 CSS 挪到 **JS** ——
  CSS 无法把媒体查询与存储值合并 ⇒ 合并只能在 store 里做；② 落地页的动效判断随之改为按根属性判断 ——
  那不是范围蔓延，而是同一个机制里的同一个缺陷（那些规则原本只认媒体查询，不改就等于交付一个在营销页上静默无效的偏好）。
  两条都写进 `.plans/ctt-web-development-plan.md` 的 S5 段与 `domains/theme-system/motion.md` ✓。
- **新立规则 R36**（AGENTS.md）：用户偏好与系统信号必须合并成一个结论，由 JS 做一次、属性承载、样式表只读属性 ✓；
  且「归零时长 ≠ 减弱动效」（时长归零仍遵守 `animation-delay`）⇒ 减弱要让动画不存在 ✓。
