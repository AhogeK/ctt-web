# 条款确认功能 QA 测试指南

> **版本**: 0.7.2 | **日期**: 2026-05-09 | **后端**: ctt-server v0.25.1

---

## 前置条件

### 环境准备

| 项目     | 要求                            | 验证方法                                                                                                 |
| -------- | ------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 后端服务 | 运行在 `localhost:8080`         | 浏览器访问 `localhost:8080/ctt-server/swagger-ui`，能看到 Swagger UI 页面                                |
| 前端服务 | 运行在 `localhost:5173`         | 浏览器访问 `localhost:5173`，能看到登录页面                                                              |
| 邮件服务 | Mailpit 运行在 `localhost:8025` | 浏览器访问 `localhost:8025`，能看到邮件列表页面                                                          |
| 测试账号 | 至少 2 个测试账号               | 1. 已接受最新条款的账号（terms_version = "1.0.0"）<br>2. 未接受最新条款的账号（terms_version = "0.9.0"） |

### 测试账号准备

**方法 1：通过注册创建新账号**

1. 打开 `localhost:5173/register`
2. 填写邮箱、显示名称、密码
3. 勾选条款复选框（文字为 `"I agree to the Terms of Service"`）
4. 点击"注册"按钮
5. 在 Mailpit (`localhost:8025`) 查收验证邮件
6. 点击邮件中的验证链接完成注册

**方法 2：通过后端模拟条款过期**

参见本文档末尾"后端模拟条款过期的三种方法"章节。

## 场景 2：注册时条款版本不匹配（USER_008）

### 目标

验证后端拒绝不匹配的条款版本，返回正确的错误码和错误信息。

### 前置条件

- 后端服务正常运行
- curl 或 Postman 工具可用

### 详细步骤

| 步骤序号 | 具体操作                                                                                                                                                                              | 预期结果                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | 打开终端或 Postman                                                                                                                                                                    | 准备发送 HTTP 请求                                                                                                                                          |
| 2        | 发送 POST 请求到 `localhost:8080/api/v1/auth/register`                                                                                                                                | 请求已发出                                                                                                                                                  |
| 3        | 设置请求头：`Content-Type: application/json`                                                                                                                                          | 请求头已设置                                                                                                                                                |

## 场景 5：API 拦截（403 AUTH_019）+ 请求重放

### 目标

| 步骤序号 | 具体操作                                                         | 预期结果                                                                                                                                                              |
| -------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | 通过后端模拟方法将已登录用户的 `terms_version` 改为 "0.9.0"      | 用户的条款版本已过期                                                                                                                                                  |
| 2        | 打开浏览器，访问 `localhost:5173/login`                          | 页面加载完成                                                                                                                                                          |
| 3        | 输入该用户的邮箱和密码，点击"登录"                               | 登录成功，跳转到 `/dashboard`（或停留在登录页，取决于登录响应的 `termsExpired`）                                                                                      |

## 已知问题 / 备注

- OAuth 流程尚不存在，涉及 OAuth 的测试不适用
- 前端使用 `AUTH_019` 和 `USER_008` 错误码检测条款过期
- 请求重放机制使用队列（`pendingTermsQueue`）存储失败的请求配置
- 接受条款后，新 JWT 替换 localStorage 中的 token
- 条款内容支持中英文，根据浏览器语言自动切换
- 拒绝条款后，用户停留在当前页面，token 未更新，队列中的请求被 reject
- **TermsDialog 有两种模式**：readOnly（注册页，只有 Close 按钮）和 normal（登录/API 拦截，有 Accept/Decline 按钮）
